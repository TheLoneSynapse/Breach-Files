02 — the machine age

      
What AI broke, and what AI found

      

        Two very different stories sit in the same decade. On one side, putting a language model into
        production created a brand-new attack surface: prompts that obey someone else, tools that act,
        and packages that never existed. On the other, machines started finding bugs in code nobody
        had time to read. Both halves are in the timeline above — filter by
        AI-Era Threats to isolate them.
      

      

        

          
The attack surface AI added

          
    
            
  • Prompt injection — instructions hidden in an email, a page or a file that the model obeys instead of you. EchoLeak (CVE-2025-32711) did it with zero clicks at CVSS 9.3.
    • 
            
  • Excessive agency — an agent with file and tool access can be talked into changing its own safety settings. CVE-2025-53773 did exactly that in a coding assistant.
    • 
            
  • Tool and supply-chain poisoning — MCP tool descriptions are read by the model but not by you. Real CVEs landed in MCP Inspector and mcp-remote in 2025.
    • 
            
  • Hallucinated dependencies — models invent package names; attackers register them. Measured at 5.2% (commercial) and 21.7% (open source) of generated code.
    • 
            
  • Deepfake identity defeat — a video call where every participant was fake moved HK$200 million. No software was broken at all.
    • 
          

        

        

          
The bugs AI found

          
    
            
  • Big Sleep, Nov 2024 — first public example of an AI agent finding an exploitable memory-safety bug in SQLite before release. Maintainers fixed it the same day.
    • 
            
  • CVE-2025-6965 — a SQLite flaw Google says was already known to attackers, found with Big Sleep and fixed before exploitation.
    • 
            
  • DARPA AIxCC, Aug 2025 — finalist systems found 54 of 63 synthetic vulnerabilities, patched 43, and turned up 18 real ones. Team Atlanta took the $4M prize.
    • 
            
  • Project Glasswing, 2026 — reported 10,000+ high or critical findings across partners; 90.6% of an independently reviewed open-source subset checked out.
    • 
            
  • The counterweight — ZeroDayBench found frontier agents still could not autonomously solve 22 novel critical vulnerabilities. Discovery scaled first; autonomy did not.
    • 
          

        

      

      

        The pattern across all of it: a model reads whatever you feed it — email, docs, tool
        descriptions, web pages — and whatever an attacker can write to, they control.
      

    

    

  


  
  

    

      
03 — no server to seize

      
Peer-to-peer threats

      

        The oldest defence against a botnet is to find the server and take it away. Peer-to-peer botnets
        remove that option: every infected machine is also part of the command network. That makes them
        harder to kill — not impossible, just more expensive. Filter the timeline by
        P2P & Botnets for the full set.
      

      

        

          
Why P2P is hard to kill

          
No central server means no domain seizure and no single sinkhole. Operators rebuild from
          surviving peers automatically. Researchers instead exploit weaknesses in the peer-discovery
          protocol itself, or wait for someone with legal authority to redirect the traffic.

        

        

          
Why it still falls

          
Operation Tovar (2014) took down Gameover Zeus by seizing domains and disrupting the
          protocol in court-authorised actions. Sality, running since 2003, was sinkholed in August 2026.
          People are a bigger vulnerability than protocols.

        

        

          
The real distribution channel

          
Cracked games and keygens remain one of the most reliable malware delivery paths in
          existence: the file is executable, unsigned, and the person running it will not report it.
          This site documents that history — it does not host or link to cracks.

05 — the cracking scene

      
Games, cracks and the arms race

      

        Copy protection has been fought over since cassette tapes could be duplicated with a second
        recorder. This is that history: the groups, the court cases, and the years the protection
        hurt legitimate players more than it ever hurt pirates.
      

      

        Scope note. This section is history. No cracks, keygens, serials or pirated software are
        hosted or linked here, and none will be. Discussing how the scene worked is not the same as
        distributing what it produced.
      

    


    


    

      

        
vocabulary

        
Scene words, defined

        
Most confusion in this area comes from treating these as synonyms. They are not.

      

      

    


    

      

        01
        
Protection raises the cost; it does not remove the risk

        
Every scheme from Sector rotators to Denuvo delayed copying. None stopped it. What Denuvo
        changed was the economics: it bought the launch window, which is where the money is.

      

      

        02
        
DRM creates single points of failure

        
Always-on checks, activation limits and remote servers mean a paid-for game stops working
        when something outside your control breaks. Spore’s three activations and The Settlers 7
        are the canonical examples.

      

      

        03
        
Protection is not the same as security

        
StarForce and SecuROM shipped kernel drivers to stop copying. Drivers are attack surface.
        Copy protection and system security pull in opposite directions, and one usually wins.

      

      

        04
        
The scene is a talent pipeline, not just a threat

        
Wozniak built blue boxes with Captain Crunch. The demoscene fed the games industry and
        security research for decades. Attitudes and enforcement both have to account for that.

      

    

  


  
  

    

      
06 — method

      
How this was built

      

        Every entry is sourced from public reporting, CVE records, court documents, vendor advisories
        and the original research papers, and each card links out to what it was based on. Where
        sources disagree or a widely repeated figure is actually an estimate, the card says so
        instead of repeating it confidently.

  • Cracks, keygens, serials, piracy links or working circumvention steps

    •
